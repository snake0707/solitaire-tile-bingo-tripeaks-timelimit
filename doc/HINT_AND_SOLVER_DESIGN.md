# Hint 提示系统 & 关卡求解器 设计方案

基于竞品 Solitaire Associations: Journey 的逆向分析，结合我方游戏机制设计。

## 我方游戏机制要点

- 移动牌列时，会同时移动源列顶部所有同类别的牌（批量移牌，只扣 1 步）
- 因此只要源列下方有暗牌，移动后必然会翻开
- 收集槽空位数量直接影响操作安全性

---

## 一、Hint 提示系统

### 1.1 设计目标

玩家点击 Hint 按钮后，高亮提示当前最有价值的一步操作。目标是让提示"看起来聪明"，引导玩家朝正确方向前进。

### 1.2 触发流程

```
玩家点击 Hint 按钮
  → 验证道具/资源是否足够，扣除消耗
  → 调用树搜索算法，计算最佳移动
  → 高亮提示卡牌及目标位置
  → 如果最佳操作是翻手牌堆，显示文字提示
```

### 1.3 搜索算法

采用 **4 层深度的权重树搜索**：

1. 从当前游戏状态出发，枚举所有合法移动
2. 对每个移动计算权重，模拟执行后递归搜索下一步（最多 4 层）
3. 选择 **4 步总权重最高** 的路径，提示该路径的第一步
4. 总权重相同时，按牌列位置从左到右取第一个

使用游戏状态的副本进行模拟，不影响真实游戏状态。

### 1.4 权重表

| 操作 | 权重 | 说明 |
|------|------|------|
| 桌面牌 → 收集区（空位 > 1，有暗牌） | **5** | 归类 + 翻牌，双重收益，最高价值 |
| 桌面牌 → 收集区（空位 > 1，无暗牌） | **4** | 安全归类，直接推进胜利 |
| 手牌展示区 → 收集区（空位 > 1） | **4** | 同样是安全归类 |
| 列间移动（翻出暗牌） | **3** | 批量移牌 + 获取新信息 |
| 桌面牌 → 收集区（空位 = 1，有暗牌） | **3** | 归类有价值但收集槽紧张，有翻牌补偿 |
| 桌面牌 → 收集区（空位 = 1，无暗牌） | **2** | 收集槽紧张，纯归类风险较高 |
| 手牌展示区 → 收集区（空位 = 1） | **2** | 同上 |
| 列间移动（无暗牌，腾空列） | **2** | 多一个缓冲位，有战术价值 |
| 手牌展示区 → 桌面列 | **2** | 整理牌面，为后续创造机会 |
| 翻手牌堆 | **1** | 被动操作，不改变局面 |
| 回收手牌堆 | **1** | 最后手段 |

### 1.5 权重设计原则

```
归类 + 翻牌 > 纯归类 > 纯翻牌 > 整理牌面 > 被动操作
收集槽紧张时（空位 = 1），各归类操作降一档
```

### 1.6 平局处理（总权重相同时）

- 优先选择能翻出暗牌的操作
- 仍平局时，按牌列位置从左到右选择
- 列间移动平局时：
  - 优先从有暗牌的列向无暗牌的列移动
  - 两列都有暗牌时，从暗牌少的列向暗牌多的列移动
  - 暗牌数相同时，按位置顺序从右往左移动

### 1.7 性能预估

- 每步合法移动通常 5~15 个
- 4 层搜索：最多约 15^4 = 50,625 个节点
- 实际远低于此（很多分支会提前终止）
- 计算耗时预估 < 50ms，可在主线程同步执行

## 二、关卡求解器

### 2.1 设计目标

验证生成的关卡是否可解。求解器需要找到一条从初始状态到全部归类完成的完整路径。用于关卡生成流程中的可解性校验。

### 2.2 与 Hint 系统的关键区别

| | Hint 系统 | 求解器 |
|--|----------|--------|
| 目标 | 提示一步好操作 | 找到完整通关路径 |
| 搜索深度 | 4 层 | 完整搜完（直到通关或判定失败） |
| 权重侧重 | 归类优先（看起来聪明） | 翻牌/腾列优先（确保能走通） |
| 收集槽空位 = 1 | 降一档（权重 2-3） | 降档但高于被动操作（权重 2） |
| 性能要求 | < 50ms（实时） | 可接受秒级（离线生成） |

### 2.3 搜索算法

采用 **贪心优先搜索 + 回溯**：

1. 从初始状态出发，枚举所有合法移动并按权重排序
2. 优先尝试权重最高的移动
3. 每步执行后检查：
   - 全部归类完成 → 求解成功，返回步数
   - 无合法移动且未完成 → 回溯到上一步，尝试下一个移动
   - 步数超过限制 → 剪枝，回溯
4. 所有路径都尝试过仍无法完成 → 关卡不可解

### 2.4 权重表

| 操作 | 权重 | 说明 |
|------|------|------|
| 列间移动（翻出暗牌） | **5** | 最高优先，获取新信息是求解关键 |
| 桌面牌 → 收集区（空位 > 1，有暗牌） | **4** | 归类 + 翻牌，进度与信息兼得 |
| 列间移动（腾空列） | **3** | 增加缓冲空间，对难关至关重要 |
| 桌面牌 → 收集区（空位 > 1，无暗牌） | **3** | 安全归类，直接推进胜利 |
| 手牌展示区 → 收集区（空位 > 1） | **3** | 同上 |
| 桌面牌 → 收集区（空位 = 1，有暗牌） | **2** | 收集槽紧张，但有翻牌补偿 |
| 桌面牌 → 收集区（空位 = 1，无暗牌） | **2** | 收集槽紧张，但仍是实质推进 |
| 手牌展示区 → 收集区（空位 = 1） | **2** | 同上 |
| 手牌展示区 → 桌面列 | **2** | 整理牌面，为后续创造机会 |
| 翻手牌堆 | **1** | 被动操作 |
| 回收手牌堆 | **1** | 最后手段 |

### 2.5 权重设计原则

```
5: 翻牌（列间移动）         — 信息为王
4: 归类+翻牌（安全时）       — 进度+信息
3: 腾空列 / 安全归类         — 灵活性 / 纯进度
2: 紧张归类 / 整理牌面       — 有价值但有风险或间接
1: 翻手牌 / 回收手牌         — 被动操作
```

核心思路：**求解器不应急于归类**。

- 过早归类会占用收集槽，减少灵活性
- 优先翻牌和腾列，创造足够操作空间后再集中归类
- 收集槽只剩 1 个空位时，归类降档但仍高于被动操作（权重 2 vs 1）
- 通过回溯机制保证：如果贪心路径走不通，求解器会回溯尝试其他选择

### 2.6 平局处理（权重相同时）

- 优先选择能翻出暗牌的操作
- 仍平局时，按牌列位置从左到右选择

### 2.7 剪枝策略

为提高求解效率，加入以下剪枝：

1. **步数上限**：超过 movesLimit 的步数直接剪枝
2. **重复状态检测**：记录已访问的游戏状态哈希，避免循环
3. **死局检测**：
   - 收集槽全满且无法归类任何牌 → 死局
   - 手牌堆为空、无暗牌、无合法移动 → 死局
4. **手牌堆回收次数限制**：避免无限循环翻手牌

### 2.8 求解结果

求解器返回：
- **可解**：返回求解步数（AI 步数）
- **不可解**：标记关卡需要重新生成

结合 accuracy 参数校验 AI 步数是否在合理范围内（参考竞品逻辑）：
```
delta = floor(movesLimit * accuracy / 100 / 2)
合理范围 = [movesLimit - delta, movesLimit + delta]
```

## 三、代码复用建议

Hint 和求解器可以共用以下模块：

```
共用模块：
├── GameState          // 游戏状态数据结构（牌列、手牌、收集槽）
├── GameState.Clone()  // 状态深拷贝（用于模拟）
├── MoveGenerator      // 枚举所有合法移动
├── MoveExecutor       // 执行/撤销一步移动
├── MoveData           // 移动数据结构（源、目标、类型、权重）
└── WeightCalculator   // 权重计算（传入不同权重表）

Hint 专用：
├── HintSearcher       // 4 层树搜索，返回最佳第一步
└── HintView           // 高亮展示

求解器专用：
├── LevelSolver        // 完整搜索 + 回溯，返回是否可解及步数
├── StateHasher        // 状态哈希（用于重复检测）
└── PruningRules       // 剪枝规则
```

权重表作为配置参数传入，同一套搜索逻辑配不同权重即可切换 Hint/求解模式。

## 四、竞品参考（SAJ 实现）

### 4.1 SAJ Hint 系统

- 搜索深度：4 层
- 权重：PlaceToHome = 4, PlaceToPlayStack = 2
- 平局时左边牌列优先
- 类：`ActionsTreeController.DoHint()` → `TryToFindMove()`

### 4.2 SAJ 验证求解器

- 搜索深度：完整求解
- 权重：PlaceToPlayStack(有牌) = 3, PlaceToHome = 2, PlaceToPlayStack(空) = 2, Stock = 1
- 每步移 1 张牌（与玩家的批量移牌不同）
- 类：`PriorityStrategySystem.Simulate()`

### 4.3 关键启示

- SAJ 的 Hint 和求解器使用**不同的权重**，目标不同
- Hint 偏向归类（对玩家直观），求解器偏向翻牌整理（确保可解）
- 我方的批量移牌机制使翻牌价值更高（一次移动可翻开多张），权重设计已体现这一点
