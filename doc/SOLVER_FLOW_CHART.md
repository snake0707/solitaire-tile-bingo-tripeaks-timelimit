# 关卡生成与求解流程图

本文档描述 `generator.html`（浏览器端）和 `generate_levels.py`（Python 端）的完整布局生成与求解流程。

---

## 一、布局生成主循环

```
┌─────────────────────────────────────────────────────────┐
│                    开始生成 Layout                        │
│              最多 2000 次尝试 (maxAttempts)                │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
              ┌─────────────────┐
              │  随机洗牌生成布局  │ generateCards() / generate_cards_for_level()
              │  (tableau + hand) │
              └────────┬────────┘
                       │
                       ▼
              ┌─────────────────┐    不通过
              │  布局质量检查     │──────────→ continue (下一次尝试)
              │ validateLayout() │
              └────────┬────────┘
                       │ 通过
                       ▼
        ┌──────────────────────────────┐
        │      条件1: 策略1 求解        │
        │  solveLevel(conservative=F)   │
        │  rejectGreedyTies=True (html) │    不通过
        │  步数上限: solveStepMax        │──────────→ continue
        └──────────────┬───────────────┘
                       │ 通过 (won=true)
                       ▼
              ┌─────────────────┐
              │   难度过滤        │    不匹配
              │ easy→priority    │──────────→ continue
              │ hard→equality    │
              └────────┬────────┘
                       │ 匹配
                       ▼
              ┌─────────────────┐
              │  步数范围检查     │    不在范围
              │ [solveStepMin,   │──────────→ continue
              │  solveStepMax]   │
              └────────┬────────┘
                       │ 在范围
                       ▼
        ┌──────────────────────────────┐
        │      条件2: 策略2 求解        │
        │  solveLevel(conservative=T)   │
        │  priorityOnly=True (html)     │    不通过 或
        │  步数上限: solveStepMax (html) │    strategyType=priority-greedy
        │           max_steps+20 (py)   │──────────→ continue
        └──────────────┬───────────────┘
                       │ 通过 (won=true, strategyType=priority)
                       ▼
              ┌─────────────────┐
              │ S2 步数范围检查   │    不在范围
              │ [solveStepMin,   │──────────→ continue
              │  solveStepMax]   │
              └────────┬────────┘
                       │ 在范围
                       ▼
        ┌──────────────────────────────┐
        │ 条件3: 策略1 纯贪心不被卡死   │    卡死
        │ greedyDeadlockCheck(con=F)   │──────────→ continue
        └──────────────┬───────────────┘
                       │ 不卡死
                       ▼
        ┌──────────────────────────────┐
        │ 条件4: 策略2 纯贪心不被卡死   │    卡死
        │ greedyDeadlockCheck(con=T)   │──────────→ continue
        └──────────────┬───────────────┘
                       │ 不卡死
                       ▼
              ┌─────────────────┐
              │   ✅ 输出 Layout  │
              │  JSON + Solutions │
              └─────────────────┘
```

**注**：条件3、4 仅在 `generator.html` 中存在，`generate_levels.py` 不做纯贪心卡死检查。
**注**：`generate_levels.py` 的策略2 不强制要求通过（S2 失败只记录 solver2Steps=-1，不淘汰 layout）。

### 布局质量检查（validateLayout）

在求解之前的快速筛选（<1ms），淘汰明显不合格的布局：

```
┌──────────────────────────────────────────────────────────────────┐
│                  validateLayout() 检查项                          │
│        手牌从数组末尾取（.pop()），检查顺序与求解器一致              │
├──────────────────────────────┬───────────────────────────────────┤
│ 条件                         │ 规则                              │
├──────────────────────────────┼───────────────────────────────────┤
│ 1. 金牌可及性                 │ 桌面面朝上有金牌，或手牌顶部5张    │
│                              │ （数组末尾5张）有金牌。             │
│                              │ 否则前期无法开槽收集。             │
├──────────────────────────────┼───────────────────────────────────┤
│ 2. 开局可操作                 │ 桌面面朝上牌之间有交互（金牌可进   │
│                              │ 空槽、或同类别可叠放），或手牌顶部  │
│                              │ 2张能和桌面互动。否则开局卡死。     │
├──────────────────────────────┼───────────────────────────────────┤
│ 3. 前期流畅性                 │ 贪心模拟前20步（从手牌末尾取牌），  │
│                              │ 要求至少完成5次拖动操作，且连续    │
│                              │ 翻牌不超过3次。否则开局体验太差。  │
└──────────────────────────────┴───────────────────────────────────┘
```

## 二、solveLevel() 内部流程

策略1 和策略2 都调用同一个 `solveLevel()`，通过参数区分行为。

```
┌─────────────────────────────────────────────────────────┐
│  solveLevel(conservative, priorityOnly, rejectGreedyTies, displaySteps)  │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
            ┌───────────────────────┐
            │ 计算 greedyStepLimit   │  = displaySteps × 0.6
            └───────────┬───────────┘
                        │
         ┌──────────────┴──────────────┐
         │                             │
         ▼                             │
┌─────────────────┐                    │
│ Priority Strategy │ (use_priority=T)  │
│   最多 3 轮       │                   │
│ seed 不同每轮     │                   │
└────────┬────────┘                    │
         │ 每轮调用                     │
         │ solveWithBacktracking(T)     │
         │                             │
         │ 成功 → 返回 strategyType=    │
         │        'priority'           │
         │                             │
         │ 3轮全败                      │
         ▼                             │
┌─────────────────┐                    │
│ Equality Strategy│ (use_priority=F)   │  ← priorityOnly=T 时跳过
│   最多 3 轮       │                   │
│ seed 不同每轮     │                   │
└────────┬────────┘                    │
         │ 每轮调用                     │
         │ solveWithBacktracking(F)     │
         │                             │
         │ 成功 → 返回 strategyType=    │
         │        'equality'           │
         │                             │
         │ 3轮全败                      │
         ▼                             │
┌──────────────────────┐               │
│ Fallback 贪心 (仅html) │ ← priorityOnly=T 时才有
│ 300步纯贪心 playout    │
│ 返回 priority-greedy   │  ← 被 generateSingleLayout 视为失败
└──────────────────────┘
```

## 三、solveWithBacktracking() 两阶段流程

每次调用 `solveWithBacktracking(usePriority)` 都执行以下两阶段：

```
┌─────────────────────────────────────────────────────────┐
│             Phase 1: 纯贪心阶段                          │
│         前 greedyStepLimit 步（displaySteps × 0.6）       │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
              ┌─────────────────┐
              │ 获取候选操作       │ getMoves()
              │ (conservative    │ 影响金牌规则)
              └────────┬────────┘
                       │
                       ▼
              ┌─────────────────────────────────┐
              │ 选择操作: pickGreedyMove()        │
              │                                  │
              │ usePriority=T:                    │
              │   按权重+tiebreak排序              │
              │   最高组内随机选一个                 │
              │   rejectGreedyTies=T时:           │
              │     多个等价候选 → 返回null → 失败   │
              │                                  │
              │ usePriority=F:                    │
              │   全随机选一个                      │
              └────────┬────────────────────────┘
                       │
                       ▼
              ┌─────────────────────────────────┐
              │ 执行操作 + 检查终止条件             │
              │                                  │
              │ ✅ 赢了 → 返回结果                  │
              │ ❌ 无操作 → Phase 1 失败            │
              │ ❌ 软死锁 → Phase 1 失败            │
              │ ❌ 连续翻牌 ≥9 → Phase 1 失败       │
              │ ❌ 连续翻拖 ≥K/L → Phase 1 失败     │
              │ ❌ 等权重随机(reject) → Phase 1 失败 │
              │ ⏩ 步数达到阈值 → 进入 Phase 2       │
              └────────┬────────────────────────┘
                       │
         ┌─────────────┴──────────────┐
         │ Phase 1 失败                │ Phase 1 完成
         │ → undo 所有操作             │ → 保留状态
         │ → 返回 null                 │ → 进入 Phase 2
         │ → 该 seed 该轮结束          │
         └─────────────┘              │
                                      ▼
┌─────────────────────────────────────────────────────────┐
│             Phase 2: 决策树回溯阶段                       │
│         从 Phase 1 结束的状态继续                          │
│         最大深度 MAX_TREE_DEPTH = 8                       │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
              ┌─────────────────────────────────┐
              │ 获取排序候选: getSortedCandidates() │
              │                                  │
              │ usePriority=T:                    │
              │   按权重+tiebreak排序              │
              │                                  │
              │ usePriority=F:                    │
              │   保持 getMoves() 原序             │
              └────────┬────────────────────────┘
                       │
                       ▼
          ┌────────────────────────────┐
          │     栈式决策树搜索           │
          │                            │
          │ 每层: 从 candidates[0] 开始  │
          │                            │
          │ 深度 < 8:                   │
          │   检查终止条件:              │
          │   ✅ 赢了 → undo全部 → 返回  │
          │   ❌ 连续翻牌≥9 → 回溯       │
          │   ❌ 连续翻拖≥K/L → 回溯     │
          │   正常 → 展开下一层          │
          │                            │
          │ 深度 = 8:                   │
          │   → greedy playout 下探     │
          │   (同Phase1的贪心选择逻辑)    │
          │   (含翻牌/翻拖限制检查)       │
          │   赢 → 返回结果              │
          │   败 → 回溯                 │
          │                            │
          │ 回溯:                       │
          │   undo当前操作               │
          │   尝试同层下一个候选          │
          │   候选用完 → pop上一层       │
          └────────────────────────────┘
                       │
                       ▼
              ┌─────────────────┐
              │ 全部探索完仍未赢  │
              │ → undo Phase 1  │
              │ → 返回 null     │
              └─────────────────┘
```

## 四、策略1 vs 策略2 参数对比

```
                    ┌─────────────┐                ┌─────────────┐
                    │   策略1 (S1) │                │   策略2 (S2) │
                    └──────┬──────┘                └──────┬──────┘
                           │                              │
            conservative = False              conservative = True
            rejectGreedyTies = True           rejectGreedyTies = True
            步数上限 = solveStepMax            步数上限 = solveStepMax
            priorityOnly = False              priorityOnly = True (html)
            → Priority 3轮 + Equality 3轮     → Priority 3轮 only
                           │                              │
                           ▼                              ▼
                    ┌──────────────┐              ┌──────────────┐
                    │ getMoves()   │              │ getMoves()   │
                    │ 金牌无限制    │              │ 金牌3条约束   │
                    │              │              │              │
                    │ ① 手牌金→槽: │              │ ① 手牌金→槽: │
                    │   有空槽即可  │              │   需桌面有    │
                    │              │              │   同类基础牌  │
                    │ ② 金牌列→列: │              │ ② 金牌列→列: │
                    │   不限制     │              │   需全部基础  │
                    │              │              │   牌已在桌面  │
                    │ ③ 手牌金→列: │              │ ③ 手牌金→列: │
                    │   不限制     │              │   无空槽时需  │
                    │              │              │   基础牌全到位│
                    └──────────────┘              └──────────────┘
```

## 五、布局淘汰规则汇总

在 Phase 1、Phase 2、greedy playout 中共享以下淘汰条件：

```
┌──────────────────────────────────────────────────────────────────┐
│                      布局淘汰条件                                 │
├──────────────────────────────┬───────────────────────────────────┤
│ 条件                         │ 触发效果                           │
├──────────────────────────────┼───────────────────────────────────┤
│ 软死锁 (isSoftDeadlock)      │ Phase1失败 / Phase2+playout死端   │
│ 连续翻牌 ≥ 9 次              │ 同上                              │
│ 连续翻拖 ≥ 7 次 (绝对上限L)   │ 同上                              │
│ 连续翻拖 ≥ 5 次              │ 同上                              │
│   且 手牌≥15 且 桌面≥3 (K)    │ （严格区，基于序列起始状态估算）     │
│ 贪心阶段等权重随机            │ Phase1失败                        │
│   (rejectGreedyTies, S1+S2) │ （Priority轮）                    │
│ 无可选操作                    │ Phase1失败 / Phase2死端            │
├──────────────────────────────┼───────────────────────────────────┤
│ 生成主循环额外条件 (仅html)    │                                   │
├──────────────────────────────┼───────────────────────────────────┤
│ S2 回溯求解失败               │ layout 淘汰                       │
│   (strategyType=priority-    │                                   │
│    greedy 视为失败)           │                                   │
│ 策略1/2 纯贪心被软卡死        │ layout 淘汰                       │
│   (greedyDeadlockCheck)     │                                   │
└──────────────────────────────┴───────────────────────────────────┘
```

## 六、关键常量

| 常量 | 值 | 含义 |
|------|---|------|
| `GREEDY_PHASE_RATIO` | 0.6 | Phase 1 占 displaySteps 的比例 |
| `MAX_TREE_DEPTH` | 8 | Phase 2 决策树最大深度 |
| `MAX_POSSIBLE_MOVES` | 50 | 单次候选数上限 |
| `MAX_SOLVER_STEPS` | 5000 | 单次求解总步数上限 |
| `MAX_SOLVER_ROUNDS` | 3 | 每种搜索算法最多轮数 |
| `MAX_CONSECUTIVE_FLIPS` | 9 | 连续翻牌上限 |
| `MAX_CONSECUTIVE_FLIP_DRAGS` | 7 | 连续翻拖绝对上限 (L) |
| `MAX_FLIP_DRAGS_STRICT` | 5 | 连续翻拖严格上限 (K) |
| `FLIP_DRAG_HAND_THRESHOLD` | 15 | 严格限制手牌阈值 (N) |
| `FLIP_DRAG_TABLEAU_THRESHOLD` | 3 | 严格限制桌面阈值 (M) |
| `maxAttempts` | 2000 | 每个 layout 最大尝试次数 |

## 七、Python 端 vs HTML 端差异

| 维度 | `generate_levels.py` | `generator.html` |
|------|---------------------|-------------------|
| S1 rejectGreedyTies | ✅ True | ✅ True |
| S2 rejectGreedyTies | ✅ True | ✅ True |
| S2 步数上限 | solveStepMax | solveStepMax |
| S2 priorityOnly | ❌ False (跑 Priority+Equality) | ✅ True (只跑 Priority) |
| S2 求解失败时 | 仅记录 solver2Steps=-1，不淘汰 layout | 直接淘汰 layout |
| S2 fallback 贪心 | 无 | 有（但 strategyType=priority-greedy 被视为失败） |
| 纯贪心卡死检查 | 无 | 条件3 + 条件4 |
| 两阶段框架 | ✅ | ✅ |
| 连续翻拖限制 | ✅ | ✅ |
